# `tileface.js` And Tile Image Pipeline

Use this note to track the current `tileface.js` behavior and the tile-image
generation model that now feeds the runtime CSS.

## Current Script

Current behavior is now:

- accepts a size-name such as `tiny-face` plus an optional output filename
- emits one base `.face` rule with:
  - `background-repeat: no-repeat`
  - `background-position: 0 0`
- emits the existing Mahjongg face-index mapping
- supports plain `url(...)` output
- supports retina-aware `image-set(...)` output through `--image-set`
- still appends the existing `.highlight:after` rule

Current output targets are:

- [normal-face.css](/c:/dev/poly-gc-react/src/gc/features/mj/assets/css/tile-appearance/normal-face.css)
- [medium-face.css](/c:/dev/poly-gc-react/src/gc/features/mj/assets/css/tile-appearance/medium-face.css)
- [small-face.css](/c:/dev/poly-gc-react/src/gc/features/mj/assets/css/tile-appearance/small-face.css)
- [tiny-face.css](/c:/dev/poly-gc-react/src/gc/features/mj/assets/css/tile-appearance/tiny-face.css)

## Current Asset Model

The runtime now uses:

- one tile body image per body material and size
- one face image per face and size
- `1x` and `@2x` variants for each runtime size
- CSS composition at runtime

Important current assumption:

- the generated face assets are now face-only PNGs sized to the face area
- they are no longer full-tile images in the runtime asset folders
- because of that, the generated CSS must keep the non-repeating top-left face
  placement rule

## Related Generator

The face and body raster assets are now generated by:

- [generate-tile-assets.js](/c:/dev/poly-gc-react/scripts/tile-css/generate-tile-assets.js)

That script currently:

- reads full-tile face source PNGs from a source directory
- crops the upper-left face region
- writes size-specific face outputs
- writes size-specific body outputs
- emits both `1x` and `@2x`
- ignores existing `@2x` files when scanning source directories
- can optionally generate composite test images, though that is no longer part
  of the normal flow

## Current Generation Flow

The current intended flow is:

1. keep the canonical source art in the normal-size face and body folders
2. run `generate-tile-assets.js` with:
   - [generate-runtime-assets.json](/c:/dev/poly-gc-react/scripts/tile-css/assets/generate-runtime-assets.json)
   - or [generate-tiny-assets.json](/c:/dev/poly-gc-react/scripts/tile-css/assets/generate-tiny-assets.json)
3. regenerate the face CSS files with `tileface.js --image-set`
4. keep the tile layout CSS unchanged because runtime geometry still uses `1x`
   CSS pixel measurements

For runtime regeneration, the main command is:

```powershell
node .\scripts\tile-css\generate-tile-assets.js --config .\scripts\tile-css\assets\generate-runtime-assets.json
node .\scripts\tile-css\tileface.js normal-face .\src\gc\features\mj\assets\css\tile-appearance\normal-face.css --image-set
node .\scripts\tile-css\tileface.js medium-face .\src\gc\features\mj\assets\css\tile-appearance\medium-face.css --image-set
node .\scripts\tile-css\tileface.js small-face .\src\gc\features\mj\assets\css\tile-appearance\small-face.css --image-set
node .\scripts\tile-css\tileface.js tiny-face .\src\gc\features\mj\assets\css\tile-appearance\tiny-face.css --image-set
```

`tile-bodies.css` is currently maintained separately, but it now references the
generated `1x/@2x` body assets for all four runtime sizes.

## Remaining Cleanup Ideas

Current script behavior is working, but future cleanup could still improve:

- move the canonical face ordering into a small shared data structure or manifest
- unify body CSS generation under a script instead of hand-editing
- add validation that expected source face/body names are present before writing
- optionally add a tiny README inside `scripts/tile-css` if local usage guidance
  grows beyond these notes

## Acceptance Check

The current implementation is in a good state if:

- face CSS maps the same runtime face indexes as before
- face CSS uses `image-set(...)` when requested
- generated face assets match face-area dimensions for each size
- generated body assets match full tile dimensions for each size
- runtime tile layout CSS remains unchanged and still uses `1x` CSS pixel
  geometry
